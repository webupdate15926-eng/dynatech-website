# دليل العميل لموقع DYNATECH

## 1. نظرة عامة

المشروع هو الموقع الرسمي ثنائي اللغة لشركة DYNATECH، ويشمل الموقع العام ولوحة إدارة محتوى مخصصة وخدمات رفع الوسائط وإرسال رسائل التواصل.

- الموقع الإنجليزي: <https://dynatecheg.com/en>
- الموقع العربي: <https://dynatecheg.com/ar>
- لوحة إدارة المحتوى: <https://dynatecheg.com/ar/admin>
- تحكم المالك الخاص: <https://dynatecheg.com/ar/super-admin>

بيانات الدخول وكلمات المرور ومفاتيح الخدمات غير محفوظة داخل GitHub لحماية المشروع.

## 2. مكونات المشروع

يشمل الموقع الصفحات التالية: الرئيسية، من نحن، شركاء التكنولوجيا، صفحات FFT وComposites United، مشروع مركز السيارات، المعلومات التقنية، الوظائف، التواصل، وإخلاء المسؤولية القانونية. كما توجد صفحة Coming Soon وصفحة إيقاف الموقع للصيانة.

يدعم قسم Tech Info الصور والفيديوهات وملفات PDF. وتدعم الأقسام المتكررة الإضافة والحذف وإعادة الترتيب من لوحة التحكم.

## 3. الخدمات المرتبطة

| الخدمة | الاستخدام |
| --- | --- |
| GitHub | حفظ الكود وسجل التعديلات |
| Hostinger | استضافة تطبيق Next.js وشهادة SSL |
| GoDaddy | تسجيل الدومين وإدارة DNS |
| Supabase | حسابات لوحة التحكم والمحتوى والمسودات |
| Cloudinary | تخزين الصور والفيديوهات وملفات PDF |
| Resend | إرسال رسائل نموذج التواصل |

يجب أن تظل ملكية هذه الحسابات تحت سيطرة العميل، مع تفعيل التحقق بخطوتين وحفظ بيانات الطوارئ في مدير كلمات مرور معتمد.

## 4. أنواع المستخدمين

### المالك Owner

يستطيع تعديل ونشر المحتوى، إدارة الوسائط، إنشاء المستخدمين وتغيير أدوارهم وكلمات مرورهم، وتعطيل أو حذف الحسابات، والتحويل بين الموقع الكامل وصفحة Coming Soon.

### المحرر Editor

يستطيع تعديل ونشر المحتوى والوسائط، لكنه لا يستطيع إدارة المستخدمين أو تغيير وضع عرض الموقع.

### دخول المالك الخاص Super Admin

حساب منفصل تمامًا عن حسابات لوحة المحتوى، ويُستخدم لتشغيل أو إيقاف وضع الصيانة الطارئ. بياناته محفوظة في متغيرات بيئة Hostinger وليست داخل قاعدة بيانات المحتوى.

## 5. تعديل ونشر المحتوى

1. اختر الصفحة من القائمة الجانبية.
2. اختر اللغة العربية أو الإنجليزية.
3. عدّل النصوص أو الصور أو العناصر المتكررة.
4. اضغط **حفظ كمسودة** للاحتفاظ بالتعديل بشكل خاص.
5. راجع الصفحة.
6. اضغط **نشر على الموقع** لإظهار التعديل للزوار.

العربية والإنجليزية منفصلتان. يجب تعديل ونشر اللغتين عندما تكون المعلومة مشتركة مثل الهاتف والبريد والعناوين.

نشر المحتوى من الداشبورد لا يحتاج إلى رفع نسخة جديدة على Hostinger.

## 6. البريد ونموذج التواصل

هناك إعدادان مختلفان:

- البريد الظاهر في الموقع والفوتر: **Global & Navigation > Connect**.
- البريد الذي يستقبل رسائل الفورم: **Contact > Contact form > Form recipient email**.

يجب تعديل بريد الاستقبال ونشره في العربية والإنجليزية إذا كان المطلوب إرسال جميع الرسائل إلى بريد واحد.

`CONTACT_FROM_EMAIL` في Hostinger هو عنوان الإرسال المعتمد لدى Resend، وليس بريد الاستقبال. بريد الزائر يُضاف كعنوان Reply-To لتسهيل الرد عليه.

## 7. إدارة الوسائط

- يمكن رفع ملف جديد أو اختيار ملف موجود من Media Library.
- يمكن استبدال الملف مع الحفاظ على نفس هويته وربطه بالمحتوى الحالي.
- لا يمكن حذف ملف نهائيًا إذا كان مستخدمًا في مسودة أو محتوى منشور؛ يجب إزالة استخدامه أولًا.
- ملفات PDF مخصصة لقسم Tech Info وتفتح من خلال رابط Cloudinary مؤقت وآمن.
- بعد ربط ملف جديد بالمحتوى يجب حفظ المسودة ثم النشر.

## 8. وضع Coming Soon والصيانة

المالك يستطيع التحويل بين الموقع الكامل وصفحة Coming Soon من لوحة التحكم، ويظهر التغيير فورًا.

وضع الصيانة يتم التحكم فيه من صفحة Super Admin. عند تفعيله تختفي صفحات الموقع العامة ويظهر محتوى Website Offline بدون الهيدر والفوتر، بينما تظل صفحات الإدارة متاحة.

## 9. إدارة الحسابات

يُفضّل إنشاء حساب مستقل لكل مستخدم وعدم مشاركة حساب واحد. يجب وجود مالكين نشطين على الأقل لضمان الاسترداد. النظام يمنع حذف أو تعطيل آخر مالك نشط.

لا يتم إرسال دعوة بريدية تلقائيًا عند إنشاء المستخدم؛ يجب مشاركة كلمة المرور معه بطريقة آمنة.

## 10. النسخ الاحتياطي

- الكود محفوظ في GitHub ويجب رفع كل إصدار إنتاجي.
- بيانات المحتوى والحسابات محفوظة في Supabase ويجب عمل نسخة احتياطية دورية.
- الوسائط المرفوعة محفوظة في Cloudinary ويجب مراقبة المساحة والباندويث.
- متغيرات البيئة والأسرار تُحفظ في مدير كلمات مرور، وليس في ملفات المشروع أو المحادثات.

## 11. قائمة مراجعة بعد أي تحديث

- [ ] مراجعة الصفحة الصحيحة واللغة الصحيحة.
- [ ] التأكد من الضغط على نشر وليس حفظ مسودة فقط.
- [ ] مراجعة نسخة الكمبيوتر والموبايل.
- [ ] مراجعة اتجاه ومحاذاة النص العربي.
- [ ] التأكد من عدم كسر الكلمات أو خروج النص من الحاوية.
- [ ] التأكد من ظهور الصور والفيديوهات وملفات PDF.
- [ ] اختبار البريد والهاتف في النسختين.
- [ ] تنفيذ اختبار فعلي لفورم التواصل بعد تغيير إعدادات البريد.

## 12. الأعطال الشائعة

### التعديل لا يظهر

تأكد من نشر الصفحة واللغة الصحيحة، ثم افتح الصفحة في نافذة خاصة أو اعمل تحديثًا بدون Cache.

### بيانات الفوتر مختلفة بين العربي والإنجليزي

عدّل وانشر صفحة Global & Navigation في كل لغة.

### الرسائل تذهب إلى البريد القديم

عدّل `Form recipient email` في صفحة Contact للغتين. تغيير البريد الظاهر في الفوتر وحده لا يغيّر مستلم الفورم.

### ملف PDF لا يفتح

تأكد من وجوده في Media Library كملف PDF من نوع Cloudinary raw، وعدم استخدام رابط Cloudinary الخام مباشرة في الواجهة.

### تعذر دخول مستخدم للداشبورد

يجب على المالك التأكد من أن الحساب Active، ثم إعادة تعيين كلمة المرور عند الحاجة.

## 13. مسؤوليات العميل بعد التسليم

- تجديد الدومين والاستضافة والخدمات المدفوعة في مواعيدها.
- الحفاظ على وصول إداري آمن لكل الحسابات الخارجية.
- حذف وصول أي موظف أو مورد لم يعد مسؤولًا عن المشروع.
- متابعة استهلاك Supabase وCloudinary وResend وHostinger.
- تدوير أي مفتاح سري يتم كشفه فورًا.
- الاحتفاظ بنسخة حديثة من البيانات وقائمة جهات الاتصال المسؤولة عن الاسترداد.
